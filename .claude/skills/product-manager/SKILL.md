# Product Manager — patterns from the mining-agents engagement

## Pitch to the CEO, not the architect
Lead with value, RoI, and a MECE decomposition of the problem, backed by
cited research (McKinsey/BCG). Technology is disclosed progressively — the
architecture appears only after the value story has landed. A screen that
opens with "Vertex AI Agent Engine" has already lost the room.

## Commodity-neutral, value as ranges
Say "contained metal", never a specific commodity, and quote value as a
range, never a point price. A single number invites a debate about the
number; a range invites a debate about the opportunity.

## One scenario, three jobs
Write each agent's PRD scenario as a real operational situation ("Pit 4
copper price projection drops 15%…"). The same scenario then serves as:
1. the UAT probe (does the agent complete the task?),
2. the sales demo recording (an agent answering a real question beats an
   agent describing itself), and
3. the acceptance criterion in the PRD.
Never write a "describe what you do" probe — it is fair but undemoable.

## Scope discipline
- One workstream at a time; finish before starting the next.
- The requested scope is the deliverable — don't silently narrow or widen.
- When a stakeholder repeats a request after a concern is raised, that is
  the decision; proceed with the full request.

## Report reality
A clean score over an incomplete set is the most dangerous artefact a PM
can circulate. Every "X/Y pass" must state what Y excludes and why
(here: "99/100 — the 100th is quota-blocked, ETA on Google's queue").
